# RepoReel — Design Document

> Generated by YC Office Hours · 2026-10-03

---

## What It Is

**RepoReel** is a CLI tool (installed like gstack) that developers run inside any project repo to automatically generate a promotional video — script, voiceover, footage, editing, and final MP4 output — using AI.

```bash
reproreel init          # scans repo, generates SKILL.md understanding
reproreel video         # generates video → saves as output.mp4 locally
reproreel video --type product-hunt  # 60-sec PH launch format
reproreel video --type explainer     # longer technical walkthrough
```

---

## Problem

Developers building projects — OSS tools, side projects, internal tools — need to **promote their work with video** to get traction. But the current workflow is:

1. Open QuickTime/Loom
2. Do 3–4 takes while narrating your own code
3. Manually write captions, descriptions
4. Upload, share

**This takes hours. Developers dread it.** So most skip it entirely. Projects go unannounced. The README is all there is.

## Target User (Day 1)

**Indie hacker launching on Product Hunt.**

- Has a project ready, needs a 60-second demo video
- Launching tonight or this weekend
- Doesn't want to spend 4 hours recording and editing
- Lives in the terminal; installs CLI tools with a single command
- Would use `reproreel video --type product-hunt` RIGHT NOW if it existed

## Core Pipeline (AI-Driven)

```
Repo Analysis → Story Creation → Script Writing → Footage Generation → Editing → MP4 Export
```

1. **Repo Analysis** — reads README, code structure, key files, git log, package.json/pyproject etc. Understands: what this project does, who it's for, what's unique.

2. **Story Creation** — generates a narrative arc: Problem → Solution → Demo → CTA. Adapts to video type (PH launch, explainer, release notes).

3. **Script Writing** — voiceover script timed to video length. 60s, 90s, or 3min depending on format.

4. **Footage Generation** — uses AI video generation (HuggingFace/similar APIs) to produce visual segments. Screen recordings are synthesized or templated.

5. **Editing / Compilation** — FFmpeg-based assembly. Overlays, captions, transitions, music bed.

6. **Export** — saves `output.mp4` (and optionally `.mov`) locally in the project folder.

## SKILL.md Architecture

Each video format is defined as a `SKILL.md` — a declarative spec the AI model reads to understand how to structure that particular video type. This is the extensibility primitive. Anyone can contribute new formats.

```
skills/
  product-hunt.md     # 60-sec, fast-paced, CTA at 50s
  explainer.md        # 3-min, technical deep-dive
  release-notes.md    # What's new in v{X}
  twitter-demo.md     # 15-sec loop, hook in first 2s
```

## Moat Question (Honest Assessment)

Current answer: "OSS projects keep growing → more demand." This is a **rising-tide argument** — not a moat.

**What the real moat could be:**
- The **repo-understanding layer** — not the video generation, but the intelligence that parses what a repo actually DOES and maps it to a compelling narrative. Generic video AI can't do this; RepoReel is trained on it.
- **Community + format library** — if 10,000 repos use RepoReel, we have a flywheel of format improvements, templates, and social proof.
- **First-mover in the CLI-native niche** — GitHub won't build this for CLI power users.

> **Action item:** Sharpen the moat. "Repo understanding → story" is where the defensibility lives.

## Status Quo Competitors

| Tool | Problem |
|------|---------|
| Loom | Manual recording, no AI script, requires human face/voice |
| Synthesia / HeyGen | No repo awareness, high cost, not dev-native |
| Screen Studio | Beautiful recording, still fully manual |
| GitHub Copilot | Code-focused, no video output |
| **Nothing** | Most devs just skip it |

RepoReel's unique position: **repo-aware, zero-human-narration, CLI-native.**
